# Business Workflows — Promax Event Platform (Proposed)

**Status:** Proposed for committee confirmation — **not fully implemented as automated workflows tonight**.

These flows describe how Yoruba Association Canberra may run Yoruba Day Canberra 2026 using the platform over time.  
They are a shared language for planning. Confirm, simplify, or replace them in committee.

## A. Attendee workflow

```
Register Interest
→ New
→ Contacted
→ Ticket Invited
→ Paid
→ Confirmed
→ Checked In
→ Attended
```

| Stage | Intent | Product status |
|-------|--------|----------------|
| Register Interest | Guest shares details on the public site | **Now** (form); live storage after Damola DB setup |
| New | Fresh interest, not yet followed up | **Soon** (RSVP CRM statuses) |
| Contacted | Committee has reached out | **Soon** |
| Ticket Invited | Ticket options / invite sent | **Later** (ticketing Phase 4) |
| Paid | Payment received | **Later** |
| Confirmed | Seat / attendance confirmed | **Soon** (status) / **Later** (with tickets) |
| Checked In | Arrived on the day | **Later** |
| Attended | Completed attendance record | **Later** |

**Committee note:** Register Interest is **not** a ticket purchase.

## B. Sponsor workflow

```
Prospect
→ Contacted
→ Interested
→ Proposal Sent
→ Negotiating
→ Confirmed
→ Benefits Delivered
→ Post Event Report
```

| Stage | Intent | Product status |
|-------|--------|----------------|
| Prospect | Possible partner identified | **Soon** (Sponsor CRM scaffold) |
| Contacted / Interested | Conversation started | **Soon** |
| Proposal Sent / Negotiating | Package discussion | **Soon** + committee process |
| Confirmed | Agreement in place | **Soon** |
| Benefits Delivered | Logos, mentions, tables fulfilled | Committee ops + **Soon** tracking |
| Post Event Report | Outcomes shared with sponsor | **Later** |

**Committee note:** Package amounts and benefits remain **to be confirmed** before public promises.

## C. Volunteer workflow

```
Expression of Interest
→ Screened
→ Assigned
→ Briefed
→ Confirmed
→ Checked In
→ Completed
```

| Stage | Intent | Product status |
|-------|--------|----------------|
| Expression of Interest | Person offers to help | **Soon** (Volunteer scaffold) |
| Screened | Suitability / availability checked | Committee process |
| Assigned / Briefed | Role and briefing given | **Soon** tracking |
| Confirmed / Checked In / Completed | Day-of readiness and close-out | **Soon** / **Later** |

## D. Committee task workflow

```
Idea
→ Task Created
→ Assigned
→ In Progress
→ Blocked
→ Completed
→ Reviewed
```

| Stage | Intent | Product status |
|-------|--------|----------------|
| Idea → Task Created | Capture work | **Soon** (Tasks scaffold) |
| Assigned / In Progress | Clear owner and motion | **Soon** |
| Blocked | Waiting on decision or dependency | **Soon** |
| Completed / Reviewed | Done and quality-checked | **Soon** |

## E. Programme workflow

```
Draft Item
→ Owner Assigned
→ Performer Confirmed
→ Time Allocated
→ Approved
→ Published
```

| Stage | Intent | Product status |
|-------|--------|----------------|
| Draft Item | Idea for the run-of-show | **Soon** (Programme scaffold) |
| Owner Assigned | Committee lead for the item | **Soon** |
| Performer Confirmed | Artist / group locked | Committee + **Soon** |
| Time Allocated | Slot on the day | **Soon** |
| Approved → Published | Ready for public programme | **Later** (public publish) |

**Committee note:** Public Experience section shows **planned highlights** only until a programme is Approved / Published.

---

## F. Communication workflow

```
Draft
→ Review
→ Approved
→ Scheduled
→ Sent
→ Logged
```

| Stage | Intent | Product status |
|-------|--------|----------------|
| Draft / Review / Approved | Human control of messaging | Committee process; Announcements scaffold **Soon** |
| Scheduled / Sent | Delivery | **Soon** / email **Now** when Resend configured (confirmations) |
| Logged | Record of what was sent | **Later** |

**Committee note:** Prefer human approval for community-wide messages.
